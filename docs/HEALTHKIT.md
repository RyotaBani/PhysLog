# ヘルスケア連携

## 設計の考え方：ハブは1つでいい

タニタも InBody も、**それぞれと個別に連携する必要はありません。**

```
タニタ体組成計 ─→ ヘルスプラネット / TANITA Record ─┐
InBody（家庭用・ジム設置）─→ InBody アプリ ────────┤
Withings / オムロン / Apple Watch ────────────────┼─→ Appleヘルスケア ─→ PhysLog
その他ヘルスケア対応機器 ────────────────────────┘
```

各メーカーのアプリがヘルスケアへ書き込むため、**PhysLog はヘルスケアだけを読めば全部に対応できます。** メーカーごとのAPI契約もOAuth実装も不要です。

Androidでも同じ構図が使えます（Health Connect が同じ役割）。

## 取り込める項目と、取り込めない項目

| 項目 | ヘルスケア | PhysLog |
|------|-----------|---------|
| 体重 | ○ | 自動取り込み |
| 体脂肪率 | ○ | 自動取り込み |
| 睡眠時間 | ○ | 自動取り込み |
| **筋肉量（骨格筋量）** | **×** | **手入力のまま** |
| 垂直跳び・50m走・握力 | × | 手入力のまま |
| トレーニング（重量×回数×セット） | △ | 手入力のまま |

### 筋肉量が取り込めない理由

ヘルスケアには「骨格筋量」に相当する項目がありません。近いものとして除脂肪体重（Lean Body Mass）はありますが、**InBody の骨格筋量とは定義が異なる別の指標**です。混同すると数値の意味が壊れるため、v1では取り込み対象から外しています。

タニタ側も、ヘルスケアへ書き出すのは体重・体脂肪率・BMI などに限られ、筋肉量は含まれません。

**ここは PhysLog にとって実は好都合です。** 体重・体脂肪率という「他アプリでも取れる情報」は自動化し、筋肉量や身体能力という「PhysLog にしかない情報」だけを手入力にすれば、入力の手間を最小化しつつ差別化が保てます。

## 動作

設定タブ →「ヘルスケア連携」

初回は「ヘルスケアと連携」をタップ → 標準の許可ダイアログ → 過去12ヶ月分を取り込み。
以降は「ヘルスケアから取り込む」で差分だけ追加されます。

### 重複と上書きの扱い

- ヘルスケア由来の記録には `externalID` が付き、手入力の記録と区別されます
- **同じ日に手入力の記録がある場合は、取り込みをスキップします**（利用者が入れた値を勝手に変えない）
- ヘルスケア由来の記録が既にある日は、値が変わっていれば更新します
- 睡眠は、その日のコンディション記録が既にあり睡眠が未入力のときだけ埋めます

### 睡眠の集計方法

ヘルスケアの睡眠は複数の区間に分割されて入ります。実装では次のように扱っています。

- 「ベッドにいた時間（inBed）」は除外し、実際に眠っていた区間だけを合算
- 就寝日ではなく**起床日**に紐づける（体感と一致するため）

## Xcode 側で必要な作業

実装とビルド設定は済んでいますが、**Xcode で1箇所だけ確認が必要です。**

```
PhysLog ターゲット → Signing & Capabilities
→ 「+ Capability」→ HealthKit を追加
```

`PhysLog.entitlements` は用意済みで `CODE_SIGN_ENTITLEMENTS` も設定済みなので、多くの場合は自動で認識されます。認識されない場合のみ上記を実行してください。

> **無料のApple IDでは HealthKit が使えない可能性があります。**
> 実機で許可ダイアログが出ない・署名エラーになる場合は、Apple Developer Program への登録が必要です。

コードは `#if canImport(HealthKit)` で囲んであるため、HealthKit が使えない環境でもビルド自体は通ります。

## 審査で気をつける点

| 項目 | 状態 |
|------|------|
| `NSHealthShareUsageDescription` に具体的な目的を記載 | 対応済み |
| プライバシーポリシーの提供（HealthKit利用時は必須） | `docs/privacy.html` あり・**要追記** |
| ヘルスケアのデータを広告に使わない | 実装上、広告SDKからアクセス不可 |
| ヘルスケアのデータを外部送信しない | 端末内保存のみ |

**Guideline 5.1.3 により、HealthKit から取得したデータを広告・マーケティング・データマイニングに使うことは禁止されています。**
PhysLog はヘルスケアのデータを端末内に保存するだけで AdMob へは一切渡していないため問題ありませんが、審査メモにその旨を明記しておくと安全です。

プライバシーポリシーに次の趣旨を追記してください。

```
本アプリは、利用者の許可を得た場合に限り、Appleヘルスケアから
体重・体脂肪率・睡眠時間を読み込みます。読み込んだデータは端末内にのみ
保存され、外部サーバーへの送信、広告目的での利用は一切行いません。
```

## Web版への影響

**ヘルスケア連携はWebでは実現できません。** ブラウザから HealthKit / Health Connect にはアクセスできないためです。

3プラットフォーム展開を考える場合、この機能の位置づけは次のようになります。

| | iOS | Android | Web |
|---|---|---|---|
| 自動取り込み | HealthKit | Health Connect | **不可** |
| 手入力 | ○ | ○ | ○ |

Capacitor でも、ネイティブプラグイン経由で iOS/Android の連携は可能です（Web版だけ手入力に限定される）。つまり「Webでは手入力のみ」と割り切れば、Capacitor 構成でも3展開は成立します。

## 今後の拡張候補

| 項目 | 内容 |
|------|------|
| バックグラウンド更新 | `HKObserverQuery` でアプリを開かなくても自動同期 |
| トレーニングの書き出し | PhysLog の記録をワークアウトとしてヘルスケアへ書き込む |
| 心拍数 | Apple Watch の安静時心拍を取り込み、コンディション分析の変数に追加 |

特に**安静時心拍数はコンディション分析と相性が良い**指標です。オーバートレーニングの兆候として使われるため、Pro機能の分析軸として追加する価値があります。
