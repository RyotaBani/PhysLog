# データ取り込み

## 方針：メーカーではなく「出口」で押さえる

メーカーごとに連携を作る方式は、原理的に「全部対応」に到達しません。タニタAPIは筋肉量の提供を2020年に終了しており、InBodyには消費者向けの公開APIがなく、新機種が出るたびに実装が増え、先方の仕様変更で壊れます。

そこで**データの出口の種類**で3経路を押さえています。

| 経路 | カバー範囲 | 取得できる項目 |
|------|-----------|--------------|
| ヘルスケア | OSハブに同期する全機器（タニタ家庭用・InBody家庭用・Withings・オムロン・Apple Watch…） | 体重・体脂肪率・睡眠 |
| CSV取り込み | ファイル出力できる全て（業務用タニタMC-980A/MC-780、施設システム、他アプリのエクスポート） | 体重・体脂肪率・**筋肉量** |
| 写真（OCR） | 上2つで取れない全て（InBodyの紙、**アプリ画面のスクリーンショット**） | 体重・体脂肪率・**筋肉量** |

3経路ともメーカー非依存なので、**新しい体組成計が出ても実装は不要**です。

### スクリーンショットOCRの位置づけ

ヘルスプラネットは公式にはエクスポートできません。非公開の内部エンドポイントを叩く方法は知られていますが、規約リスクがあり仕様変更で壊れるため採用していません。

代わりに**アプリ画面のスクリーンショットをOCRする**ことで、同じ目的を安全に達成しています。読み取りは Vision フレームワークで端末内完結し、画像は外部へ送信されません。

## CSV取り込みの仕様

### 文字コード

UTF-8 → Shift_JIS → EUC-JP → UTF-16 の順に試し、文字化けが少ないものを採用します。**業務用タニタの出力は Shift_JIS が多い**ため、UTF-8 決め打ちにすると文字化けします。BOM も除去します。

### 列の自動推定

見出しから各列の意味を推定します。全角・半角・大文字小文字・スペース・記号のゆれを吸収したうえで、完全一致 → 部分一致の順で判定します。

推定結果は取り込み前に画面で確認・修正できます。自動推定はあくまで初期値です。

**紛らわしい組の扱い**

`体脂肪量` と `体脂肪率` は別項目です。前者を先に除外してから判定しているため、取り違えません。

### 検証済みの形式

| 形式 | 結果 |
|------|------|
| タニタ業務用（`測定日時,ID,体重(kg),体脂肪率(%),筋肉量(kg),体脂肪量(kg),BMI`） | 日付・体重・体脂肪率・筋肉量を正しく判定。ID / 体脂肪量 / BMI は除外 |
| InBody英語見出し（`Test Date,Weight,PBF,SMM`） | 全4列を正しく判定 |
| 全角文字・引用符・フィールド内改行・カンマ入りメモ | 正しくパース |

### 対応している日付書式

`yyyy/MM/dd HH:mm:ss` / `yyyy-MM-dd` / `yyyy.MM.dd` / `yyyyMMddHHmmss` / `yyyy年MM月dd日` / `yy/MM/dd` など。全角数字も変換して処理します。

---

## 上書きの扱い

**どの経路でも、入力済みの値を上書きしません。**

- 同じ日に既存の記録がある場合、**空いている項目だけ**を埋めます
- 手入力した値が取り込みで書き換わることはありません
- ヘルスケア由来の記録は `externalID` で区別され、再取り込み時に更新されます

記録アプリで最もやってはいけないのが「利用者が入れた値を勝手に変える」ことなので、ここは厳密にしています。

---

## 使い方

設定タブ →「データの取り込み」

**CSV**: ファイルを選ぶ → 列の対応を確認 → 内容を確認 → 取り込む

**写真**: 写真を選ぶ → 自動で読み取り → 内容を確認 → 取り込む

OCRは読み取れた文字列も画面に表示されるため、数値が間違っていないか確認できます。

---

## 既知の限界

**OCRの精度は撮影条件に依存します。** 結果用紙が画面いっぱいに、明るい場所で、傾きなく写っている必要があります。1枚から1件のみ取り込む設計にしているため、複数回分がまとまった用紙は1件ずつになります。

**部位別筋肉量には未対応です。** InBodyの部位別データ（右腕・左腕・体幹・右脚・左脚）はモデルに項目がないため取り込めません。必要なら `BodyMeasurement` に項目を追加する拡張が要ります。

**写真からの取り込みは日付が読めない場合、当日として扱います。** 確認画面で日付が正しいかを見てください。

## Web版・Android版への展開

CSV取り込みは**3プラットフォームすべてで同じ実装方針が使えます**。ファイル選択とパースだけなので、OS固有のAPIに依存しません。

OCRは各OSの機能に依存します。

| 経路 | iOS | Android | Web |
|------|-----|---------|-----|
| ヘルスケア | HealthKit | Health Connect | 不可 |
| CSV | ○ | ○ | ○ |
| OCR | Vision | ML Kit | Tesseract.js（精度は劣る） |
